# Code Conventions

Use this file to capture repo-specific development habits.

## Code Style

- Follow existing naming, formatting, and file organization.
- Prefer small, local changes.
- Add new abstractions only when they reduce real duplication or risk.

## Testing Expectations

- Update tests when behavior changes.
- Add regression coverage for bug fixes when practical.
- Mention tests that were not run.

## Documentation Expectations

- Update docs when commands, setup, config, or user-facing behavior changes.

## Agent Behavior

- Ask for clarification when a task changes architecture, data, security, deployment, or product scope.
- Treat generated files, lockfiles, migrations, and config changes as higher risk.
